Delegate without giving up control

The queue around the agents you already use.

A cloud agent is easy to start, but it chooses the environment. A local agent has your real toolchain, but usually waits in a terminal. Bivy gives local agents a durable queue and a control surface.

Stay in the loop

Walk away from the terminal. Not from the work.

A Bivy session is durable across disconnects and daemon restarts. Start it in your terminal, pick it up in the app, and get notified only when your judgment is needed.

  • Approve with context. See the proposed command, raw tool input, and diff before deciding.
  • Recover instead of restart. Rewind a bad turn or fork the transcript and uncommitted work to another agent or node.
  • Use a real terminal when needed. A full PTY is one tap away, including existing tmux, zellij, or screen sessions.
  • Burst without buying Bivy compute. Launch an ephemeral runner in your own Fly.io, Hetzner, or AWS account.

A narrow trust boundary

Your repository does not become Bivy's data.

The node on your machine owns the repository, model credentials, and agent process. It dials out to an end-to-end encrypted relay, so you do not open an inbound port.

Before you install

What to expect.

Bivy is 0.x software. The core session loop is used daily, but interfaces can change and agent integrations do not all have the same capabilities.

What do I need?

A Mac or Linux machine and a model-provider login or API key. The installer checks for Node 22.19+, runs the setup wizard, installs a background service, and pairs the browser or phone app. Windows is not currently supported.

Are all 19 agent integrations equally complete?

No. Pi and Claude Code have the deepest Bivy integration; many others are Beta and inherit upstream gaps in resume, model selection, or approvals. Check the runtime support matrix before choosing an agent for unattended work.

When should I use a hosted cloud agent instead?

Choose one when you want bundled inference, managed compute, and the least setup—or when one vendor's agent and remote experience already cover your workflow. Choose Bivy when execution location, existing tools and network access, mixed agents, or self-hosting matter more.

Does Bivy sandbox the agent?

Sandbox support depends on the agent. Some enforce native sandbox tiers; others are governed at filesystem, MCP, and network boundaries. Bivy does not ship an OS-level jail in 0.1. Catastrophic operations are blocked and force-push, publish, deploy, and sudo require approval.

Can I self-host everything?

Yes. The node, web client, relay, and baseline control plane are source-available under FSL-1.1-ALv2. Self-hosting is unsupported and community best-effort; each release converts to Apache-2.0 after two years.
